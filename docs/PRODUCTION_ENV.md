# Production environment checklist (Render dashboard)

Set these on the `scanin` service. Names are exactly what the app reads. There is no `HMAC_SECRET` or `CORS_ORIGIN`: QR signing uses `QR_KEYS`, and the API and web app share one origin, so no CORS is needed.

| Variable                                                                        | Value                                                                                                                                                                                               | Required |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `NODE_ENV`                                                                      | `production` (in `render.yaml`)                                                                                                                                                                     | yes      |
| `APP_ORIGIN`                                                                    | `https://<your-domain>` exactly, no trailing slash                                                                                                                                                  | yes      |
| `DATABASE_URL`                                                                  | Neon **direct** (non-pooled) URL, role `scanin_app`, ends `?sslmode=require`                                                                                                                        | yes      |
| `MIGRATOR_DATABASE_URL`                                                         | Neon direct URL, the owner role. Used by the pre-deploy step only                                                                                                                                   | yes      |
| `RETENTION_DATABASE_URL`                                                        | Neon direct URL, role `scanin_retention`. Without it, nothing is ever purged                                                                                                                        | yes      |
| `RESEND_API_KEY`                                                                | Resend key, sending access only                                                                                                                                                                     | yes      |
| `MAIL_FROM`                                                                     | `ScanIn <no-reply@your-domain>`, on a domain verified in Resend                                                                                                                                     | yes      |
| `IP_HASH_SECRET`                                                                | 32+ random characters (generated by `render.yaml`)                                                                                                                                                  | yes      |
| `QR_KEYS`                                                                       | `k1:<base64url>`, from `node -e "console.log('k1:'+require('crypto').randomBytes(32).toString('base64url'))"`                                                                                       | yes      |
| `QR_ACTIVE_KID`                                                                 | `k1` (must be a key id listed in `QR_KEYS`)                                                                                                                                                         | yes      |
| `TRUST_PROXY`                                                                   | `true`                                                                                                                                                                                              | yes      |
| `DEVICE_POLICY`                                                                 | `BLOCK` (default) rejects a second student on the same phone in one class; `FLAG` records it and raises a flag                                                                                      | no       |
| `REGISTER_MAX_PER_IP_PER_HOUR`, `LOGIN_MAX_FAILURES_PER_IP`                     | Sign-ups per hour (`100`) and failed sign-ins per 15 minutes (`30`) allowed from one public address. Campus Wi-Fi puts a whole class behind one address, so raise these if students are turned away | no       |
| `HEADCOUNT_TOLERANCE_PERCENT`, `HEADCOUNT_TOLERANCE_MIN`                        | How far recorded attendance may exceed the lecturer's headcount before it is flagged for review: `max(MIN, PERCENT % of the headcount)`. Defaults `15` and `3`                                      | no       |
| `HEADCOUNT_MAX`, `HEADCOUNT_STALE_MINUTES`                                      | Largest headcount accepted (`2000`); minutes before a headcount with later check-ins is shown as out of date (`30`)                                                                                 | no       |
| `SPOT_CHECK_DEFAULT_SIZE`, `SPOT_CHECK_MAX_SIZE`, `SPOT_CHECK_HISTORY_SESSIONS` | Spot-check sample size (`5`, at most `20`) and how many earlier sessions make a student less likely to be picked again (`2`)                                                                        | no       |
| `API_PORT`                                                                      | `10000`                                                                                                                                                                                             | yes      |
| `WEB_DIST_DIR`                                                                  | `/opt/render/project/src/apps/web/dist`                                                                                                                                                             | yes      |
| `EXPORT_DIR`                                                                    | `/tmp/scanin-exports`                                                                                                                                                                               | no       |
| `AUDIT_CHECKPOINT_DIR`                                                          | leave unset until someone independent of the database owner owns the location                                                                                                                       | no       |
| `ALLOW_INSECURE_COOKIES`                                                        | never set in production (startup refuses it)                                                                                                                                                        | no       |

Do not put `OPERATOR_DATABASE_URL` on Render. Run the operator CLI from a trusted laptop.

## One-time database setup on Neon

1. Create the project in the same region as the Render service. Use the **direct** connection string (the pooled one routes through PgBouncer, which does not suit migrations that take session-level locks).
2. As the owner role, create the three login roles once. Use three different strong passwords:
   ```sh
   MIGRATOR_DATABASE_URL="<owner direct url>" \
   DB_APP_PASSWORD=... DB_RETENTION_PASSWORD=... DB_OPERATOR_PASSWORD=... \
     node apps/api/dist/db/setup.js --create-roles
   ```
   (after `pnpm build`). Defaults: `scanin_app`, `scanin_retention`, `scanin_operator`.
3. Build `DATABASE_URL` and `RETENTION_DATABASE_URL` from the same host, with those role names and passwords.

## Cloudflare

- Proxy (orange cloud) the hostname to the Render custom domain.
- SSL/TLS mode: **Full (strict)**. Turn on **Always Use HTTPS**.
- Cache: bypass for `/api/*` (the API already sends `Cache-Control: no-store`).
- Do not enable rewriting features that alter HTML or scripts (Rocket Loader, Auto Minify): the Content-Security-Policy blocks them.

## E-mail (Resend)

1. In Resend, add and verify your sending domain (the DNS records go in Cloudflare; set them to **DNS only**, not proxied).
2. Create an API key with sending access only and set it as `RESEND_API_KEY`.
3. Set `MAIL_FROM` to an address on that domain, for example `ScanIn <no-reply@your-domain>`.

Production refuses to start without both. The verification link is never written to the logs.
